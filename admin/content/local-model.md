# FinDone 로컬 모델 화면 문구

이 파일은 Admin 로컬 모델 화면, Viewer 로컬 모델 화면, 앱 소개의 Admin 페이지가 함께 사용합니다.
`<!-- section:... -->` 주석은 코드가 섹션을 찾는 키이므로 삭제하거나 바꾸지 말고, 각 섹션의 제목과 본문은 자유롭게 수정해도 됩니다.

<!-- section:page-intro -->
## 로컬 모델 현황

외부 LLM API 없이 저장소의 검토된 데이터와 로컬 실행 코드만으로 진행하는 `용어 → 설명 선택` 개념형 오지선다 실험, 자동 검수와 Owner 확인 상태를 한 화면에서 확인합니다.

세부 실험값은 Owner에게만 보이고, Viewer에게는 전체 수치 대신 아래 모델링 과정만 공개합니다.

<!-- section:modeling-process -->
## 모델링 과정

검토된 금융 개념을 문제로 제시하고, 같은 유형의 설명 사실 다섯 개 중 올바른 설명을 고르는 문항은행을 만듭니다. 관계형 선지는 수식을 그대로 노출하지 않고 증가·감소·비중·반대 방향 같은 말로 풀어 씁니다.

### 1. 기준 데이터와 원본 준비

기존 앱 콘텐츠 DB의 개념명·정의·직관·핵심 관계와 출처를 기준점으로 고정합니다. 핵심 관계에 수식이 있으면 별도의 검토된 자연어 관계 사실로 바꾸며, 원문 전체를 외부 API로 보내지 않습니다.

### 2. 학습셋과 평가셋 구성

문제에는 용어만 넣고 선지에는 정의·직관·자연어 관계 설명을 넣습니다. 같은 문항의 다섯 선지는 반드시 같은 유형이며, 같은 개념이 train·validation·test에 동시에 섞이지 않도록 요소 단위로 분리합니다.

### 3. 임베딩·검색·랭커 실험

TF-IDF 기준선과 의미 임베딩 후보를 이용해 대상 용어와 혼동하기 좋은 다른 개념의 설명을 찾습니다. 모델은 설명을 새로 쓰지 않고 검토된 오답 설명의 순위만 정하며, validation으로 구성을 고른 뒤 한 구성만 test에서 확인합니다.

### 4. 앱 콘텐츠 DB 후보 생성

선택된 결과를 그대로 배포하지 않고 문제 방향, 설명 선지 5개, 정답 1개, 출처 연결, 용어명 누출, 수식 노출, 중복과 복수 정답 여부를 결정론 규칙으로 검사합니다.

### 5. 자동 검수·예외 확인과 릴리스

랭커 합의도와 선택 경계뿐 아니라 관계 설명의 자연어 여부와 다섯 선지의 문체 균형을 자동 검사합니다. 차단 문항은 수정하고 불안정한 예외만 Owner가 확인한 뒤, 새 검수 입력 SHA-256에 묶인 배치 승인이 있어야 `release_ready`가 됩니다.

<!-- section:concept-model -->
## 개념형 오지선다 모델

이 모델은 금융 지식을 새로 생성하는 범용 언어 모델이 아니라, 제시된 용어에 대해 검토된 설명 선지 중 교육적으로 좋은 오답 후보를 골라 순위를 매기는 로컬 랭커입니다.

화면의 test 지표는 선택된 한 구성의 약지도 재현 결과이며 실제 사용자 문제 품질 정확도를 뜻하지 않습니다. 자동 검수 통과율도 품질 정확도가 아니라 규칙·랭커 합의·변경 영향 검사의 처리 결과입니다.

<!-- section:experiment-flow -->
## 실험 전개 과정

비교 조건을 한 번에 모두 바꾸지 않고 기준선부터 후보 모델 선택까지 단계적으로 좁혀, 어떤 변경이 성능과 실행 비용에 영향을 줬는지 추적합니다.

- **기준선 확정**: TF-IDF와 기준 가중치로 데이터 분할·평가 코드가 정상인지 먼저 확인합니다.
- **검색 후보 비교**: 어휘 검색과 의미 검색의 혼합비를 바꾸며 Recall@20으로 정답 후보를 놓치지 않는지 봅니다.
- **랭커 학습**: pairwise logistic과 선택 가능한 트리 계열 랭커를 train 쌍으로 학습하고 정규화 강도를 비교합니다.
- **구성 선택**: validation NDCG@4가 최고점 허용 범위 안이면 더 가볍고 재현 가능한 구성을 우선합니다.
- **고정 test 평가**: 선택을 끝낸 뒤 한 번만 test를 열어 NDCG@4·Precision@4를 기록하고 사람 검토 게이트를 적용합니다.

<!-- section:embedding-comparison -->
## 임베딩 후보 비교

후보별 최고 validation 실행만 남겨 같은 기준으로 비교합니다. 선택 표시는 무조건 최고 점수라는 뜻이 아니라, 허용 오차 안의 성능·모델 크기·인코딩 비용·재현성을 함께 고려한 결과입니다.

TF-IDF는 가벼운 기준선이고, 다국어 임베딩은 표현이 다른 개념을 의미적으로 찾기 위한 후보입니다. 인코딩 실패나 캐시 사용 여부도 숨기지 않고 함께 기록합니다.

<!-- section:quality-gates -->
## 문항 품질과 릴리스 게이트

모델 점수가 높아도 문제 방향 위반, 용어명·코드 누출, 관계형 수식 노출, 중복·복수 정답, 자동 차단, 미확인 예외, Owner 배치 승인 누락 중 하나라도 있으면 문항은행 릴리스를 막습니다.

검수 프로필은 reference baseline에서 보수·완화 방향으로 한 변수씩 조정하고 validation 예외율로 선택합니다. test는 프로필 선택에 사용하지 않으며, 선택 근거와 전체 민감도 실험을 기록합니다.

<!-- section:experiment-log -->
## 누적 실험 기록

v2 첫 실행부터 선택 임베딩·랭커·validation·test, 자동 검수 프로필, 변경 영향, 예외 큐와 Markdown 보고서를 새로 기록합니다. 폐기된 `설명 → 용어` v1 실험은 현재 이력에 포함하지 않습니다.

`CANDIDATE`는 자동 검수 예외 확인이나 Owner 배치 승인이 남은 개발 상태이고, `READY`만 릴리스 후보입니다.

<!-- section:rule-model -->
## 앱 콘텐츠 변환 규칙 모델

오지선다 랭커와 별도로, 구조화 fragment를 앱 스키마에 맞는 콘텐츠 DB로 바꾸는 결정론 변환기가 있습니다. 같은 입력이면 같은 SQLite 해시가 나와야 하며 외부 LLM API는 호출하지 않습니다.

이 영역의 100%는 머신러닝 일반화 정확도가 아니라 필수 필드·출처 추적·골든셋 assertion을 현재 규칙이 모두 충족했다는 뜻입니다.

<!-- section:metrics-guide -->
## 지표 읽는 법

준비도·학습률·골든셋 정확도는 서로 다른 질문에 답하므로 하나의 ‘모델 성능’으로 합쳐 해석하지 않습니다.

- **준비도**: 코퍼스 커버리지, 필수 필드, 출처 추적, 골든셋 검사 등을 가중 합산한 운영 준비 지표입니다.
- **학습률**: 목표로 잡은 앱 요소 중 현재 구조화 규칙과 데이터에 반영된 비율입니다.
- **골든셋 정확도**: 사람이 미리 정한 기대 필드와 결정론 출력이 일치한 비율이며, 보수적인 Wilson 95% 하한도 함께 봅니다.
- **빌드 성능**: 같은 입력을 SQLite로 만드는 시간·처리량·해시 재현성을 뜻합니다.
