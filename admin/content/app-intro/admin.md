## 앱에 들어갈 재료를 정리해요.

Admin에서 원본 자료와 출처를 등록하고, 앱에서 보여줄 개념과 오답 후보를 구조화해요. Owner만 내용을 편집할 수 있고 Viewer는 어떤 항목으로 구성되는지만 볼 수 있어요.

- **원본 자료** — 출처, 파일과 수집 상태를 관리.
- **개념 DB** — 정의, 핵심 관계, 직관, 수식과 학습 본문을 편집.
- **오답 후보** — 객관식 문제에 사용할 그럴듯한 오답과 근거를 연결.

## 바로 앱으로 보내지는 않아요.

작성한 내용은 먼저 자동 검증과 승인 검토를 거쳐요. 필수 필드, 출처, 수식과 콘텐츠 관계를 확인하고 문제가 남아 있으면 릴리스를 만들 수 없게 해두었어요.

- **자동 검증** — 누락, 형식 오류와 콘텐츠 규칙을 검사.
- **승인 검토** — 변경 전후와 근거를 확인한 뒤 승인 또는 반려.
- **앱 반영** — 승인된 수정본으로 SQLite DB와 manifest를 생성하고 stable 채널에 공개.

## Admin에서 앱으로 이렇게 이동해요.

stable 릴리스가 활성화되면 Admin의 공개 HTTPS endpoint가 새 콘텐츠 버전과 다운로드 주소를 제공해요. 실제 manifest와 DB 파일은 짧은 시간만 유효한 서명 URL로 전달돼요.

## 앱은 실행할 때 새 버전을 확인해요.

현재보다 높은 콘텐츠 버전이 있으면 앱이 manifest와 SQLite DB를 임시 파일로 내려받아요. 스키마, 최소 앱 버전, 파일 크기와 SHA-256 해시가 모두 일치할 때만 새 콘텐츠로 교체해요.

## 업데이트에 실패해도 공부는 계속할 수 있어요.

네트워크가 끊기거나 검증에 실패하면 새 파일을 설치하지 않고 마지막으로 정상 확인된 콘텐츠를 그대로 사용해요. 오답, 북마크, 진도와 메모 같은 개인 데이터는 콘텐츠 DB와 분리되어 있어서 콘텐츠가 바뀌어도 유지돼요.
